# 3～5 分钟演示脚本

## 演示前准备

```powershell
python scripts/import_jobs.py --input data/evaluation/jobs.json --db data/app.db
streamlit run app.py
```

使用 `data/evaluation/demo_resume.md`，不要在公开演示中上传真实未脱敏简历。

## 时间线

1. **0:00～0:30 痛点与定位**：岗位 JD 表述不统一，候选人难以比较，也容易为了关键词误改简历。本项目把硬规则、语义和证据拆开，不让模型直接决定总分。
2. **0:30～1:10 简历解析**：上传合成简历，展示技能、教育和项目原文，并强调用户可人工修正。
3. **1:10～1:35 岗位库**：展示 36 条合成岗位、上海默认筛选、截止状态与 CSV/JSON 导入。
4. **1:35～2:20 岗位推荐**：运行 Top-5，打开第一名，解释六项分数、技能命中、缺口和证据。
5. **2:20～3:00 简历优化**：对比绿色“可直接修改”和“完成相关工作后才能加入”，说明如何防止编造经历。
6. **3:00～3:30 模拟面试**：展示项目深挖、岗位知识、技能缺口、系统设计和行为题。
7. **3:30～4:10 评测**：展示技能 F1、Recall、MRR、nDCG 与五组消融，并主动说明合成集限制。
8. **4:10～4:30 工程与隐私**：SQLite、本地离线、完整测试、Docker、删除记录和不存完整简历。

## 简历项目描述

**秋招雷达 AI｜岗位匹配与简历优化 Agent**：构建支持 PDF/DOCX/TXT/Markdown 的简历解析与上海 AI 校招岗位匹配系统，设计硬规则、项目技能与离线语义相似度的六维融合评分，输出可追溯的技能缺口、简历建议及岗位面试题；实现 SQLite 去重存储、Markdown 报告、Streamlit/Docker 部署，并用 F1、Recall@K、MRR、nDCG 和五组消融实验验证完整管线。

## 面试展开点

- 为什么地点和学历是硬约束，而不是相似度的一部分？
- 如何避免技能别名漏召回，以及别名表的维护成本？
- 为什么合成集 nDCG 很高但 Recall@5 不高？
- 为什么离线 hashing 向量只是基线，BGE-M3 替换点在哪里？
- 证据约束如何阻止系统把“建议学习”写成“已经掌握”？
- 从单机 Demo 到生产系统还需要哪些权限、监控、数据治理和评测机制？
