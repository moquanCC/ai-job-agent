# 评测说明

## 数据

仓库包含 36 条合成岗位与 3 份合成简历，全部在文件中明确作为测试数据使用。岗位覆盖大模型应用、机器学习、数据挖掘、搜索推荐、NLP 和 AI 应用开发六类；每份简历对岗位有 0～3 的分级相关性标签。

## 指标

- 技能提取：Precision、Recall、F1。
- 排序：Recall@5、Recall@10、MRR、nDCG@5、nDCG@10。
- 工程：本地完整评测运行时间。

## 方法

`python scripts/run_evaluation.py` 比较五组可复现配置：关键词、语义、关键词+语义、规则融合、完整方法。每组权重和向量后端会一并写入 `data/evaluation/results.json`。

## 当前结果

当前合成集上技能提取 F1 为 1.0，完整方法 MRR 与 nDCG@5 为 1.0，Recall@5 为 0.2778。Recall@5 较低的主要原因是每个简历有 18 个被定义为“相关”的重复模板岗位，而 Top-5 最多召回 5 个；这说明指标解释必须结合标签密度，不能只看一个数字。

同时，规则融合和完整方法在当前数据上没有显著拉开差距。这不是“完整方法无效”的充分证据，而是合成模板过于整齐、项目相关性信号与技能信号高度重合。后续真实实验应扩大样本差异并加入困难负样本。

## 复现实验

```powershell
python scripts/generate_sample_data.py
python scripts/run_evaluation.py
```

## 真实验收建议

1. 使用 3～5 份脱敏真实简历和 30～50 条仍可核验来源的上海校招 JD。
2. 由至少两名标注者独立给出 0～3 相关性，记录分歧与裁决。
3. 冻结数据版本、权重、Embedding 模型和运行环境。
4. 同时报告均值、逐简历结果、延迟、失败率和 API 成本。
5. 达到交接阈值前，重点分析错误类型而不是调参追逐单一指标。
